**Tax Register** - a tax register records what was collected, what was paid, what was withheld and when each filing is due, period by period. Instead of a spreadsheet only one person understands, each tax period becomes a row with a named owner, a status and a review rhythm. 21 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per tax period, 21 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 21 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Tax Record`; `Tax Type`; `Tax Period`; `Period Start`.
- `Period End`; `Tax Collected on Sales`; `Tax Paid on Purchases`; `Withholding Tax Deducted`.
- Plus 13 more: `Withholding Tax Paid to Us`, `Net Tax Payable`, `Currency`, `Filing Due Date`, `Filed Date`, `Payment Date` and 7 more.

Field types break down as 1 auto ID, 6 text, 1 long text, 2 select, 1 number, 5 currency and 5 date. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Filing deadlines are tracked as calendar reminders, so a missed one is found out about late.

That is the argument for tax register: tax mistakes are calculation errors, and calculations belong in software. This should hold the record and the status, not the arithmetic.

Three things break at once without it. Nobody can answer "show me every tax period we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per tax period fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is a couple of hours of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A starter-tier system: most small teams need it from day one.

**What it does not do:** calculate tax, file returns or give tax advice.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** Which taxes are you registered for?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - keep the tax register as a record of periods, amounts and filing status, and let the accountant or filing tool do the calculation.
4. **Build only on request** - CSV, SQL DDL, JSON Schema, a Notion mapping or an Excel workbook, data only.

The intended workflow is: Period opened → Source data recorded → Amount entered → Filed → Reconciled

## Frequently asked questions

### What is the difference between tax register and a spreadsheet?

A spreadsheet is a container. Tax Register is a defined set of 21 fields, a known owner and a stated review rhythm, which is what makes the data trustworthy. The skill emits the same field list as CSV, SQL and JSON Schema so the structure survives the move out of the sheet.

### What fields does a tax register system usually include?

At minimum Tax Record, Tax Type, Tax Period, Period Start. A complete version also covers Period End, Tax Collected on Sales, Tax Paid on Purchases, Withholding Tax Deducted. This template ships all 21, with types fixed rather than guessed.

### Do I need tax register if my team is small?

Yes - a starter-tier system, and most small teams need it from day one. The deciding question is not headcount, it is whether anyone can answer "show me every tax period we have" without checking with a person first.

### What does this system not do?

- Empty template only. It does not compute payroll, tax, leave balances or KPIs.

Tax Register touches decisions with legal, financial or employment consequences. ## SQL reference

```sql
CREATE TABLE tax_register (
  tax_record VARCHAR(255),
  tax_type VARCHAR(100) NOT NULL,
  tax_period VARCHAR(255),
  period_start DATE NOT NULL,
  period_end DATE NOT NULL,
  tax_collected_on_sales NUMERIC(14,2) NOT NULL,
  tax_paid_on_purchases NUMERIC(14,2) NOT NULL,
  withholding_tax_deducted NUMERIC(14,2) NOT NULL,
  withholding_tax_paid_to_us NUMERIC(14,2) NOT NULL,
  net_tax_payable NUMERIC(14,2) NOT NULL,
  currency VARCHAR(255),
  filing_due_date DATE NOT NULL,
  filed_date DATE NOT NULL,
  payment_date DATE NOT NULL,
  filing_reference VARCHAR(255),
  prepared_by VARCHAR(255),
  reviewed_by VARCHAR(255),
  days_to_due NUMERIC NOT NULL,
  status VARCHAR(100) NOT NULL,
  notes TEXT,
  tax_id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_tax_register_status ON tax_register (status);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
