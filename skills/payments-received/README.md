**Payments Received** - a payment record matches money received to the invoice it settles, so what remains outstanding is a number rather than an opinion. Instead of a spreadsheet only one person understands, each payment becomes a row with a named owner, a status and a review rhythm. 13 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per payment, 13 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 13 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Payment Reference`; `Client`; `Invoice`; `Amount`.
- `Currency`; `Payment Date`; `Payment Method`; `Withholding Tax Deducted`.
- Plus 5 more: `Bank Account`, `Received By`, `Receipt Sent`, `Notes`, `Payment ID`.

Field types break down as 1 auto ID, 5 text, 1 long text, 1 select, 1 checkbox, 2 currency, 1 date and 1 relation. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Payments arrive without references, so the ledger and the bank disagree.

That is the argument for payments received: reconciliation is the control that matters. If every payment is matched to an invoice number, the rest is reporting.

Three things break at once without it. Nobody can answer "show me every payment we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per payment fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is under an hour of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A starter-tier system: most small teams need it from day one.

**What it does not do:** move money or connect to a bank feed.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** How do you receive payments today?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - keep a receipts log matched to an invoice, and treat the bank statement as the source rather than re-keying both sides.
4. **Build only on request** - CSV, SQL DDL, JSON Schema, a Notion mapping or an Excel workbook, data only.

The intended workflow is: Payment received → Matched to invoice → Recorded → Reconciled → Disputed if unmatched

## SQL reference

```sql
CREATE TABLE payments_received (
  payment_reference VARCHAR(255),
  client VARCHAR(255),
  invoice VARCHAR(255),  -- relation -> target record
  amount NUMERIC(14,2) NOT NULL,
  currency VARCHAR(255),
  payment_date DATE NOT NULL,
  payment_method VARCHAR(100) NOT NULL,
  withholding_tax_deducted NUMERIC(14,2) NOT NULL,
  bank_account VARCHAR(255),
  received_by VARCHAR(255),
  receipt_sent BOOLEAN NOT NULL,
  notes TEXT,
  payment_id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
