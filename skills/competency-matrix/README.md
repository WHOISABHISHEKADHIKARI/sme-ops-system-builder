**Competency Matrix** - a competency matrix defines the skills each role requires and the level expected, so gaps can be named rather than guessed at. Instead of a spreadsheet only one person understands, each competency requirement becomes a row with a named owner, a status and a review rhythm. 9 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per competency requirement, 9 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 9 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Competency`; `Category`; `Job Title`; `Grade Level`.
- `Expected Level`; `Description`; `Assessment Method`; `Linked Skill Area`.
- Plus 1 more: `Competency ID`.

Field types break down as 1 auto ID, 3 text, 1 long text, 3 select and 1 relation. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Skill requirements live in the heads of the two people who wrote the job descriptions.

That is the argument for competency matrix: a competency matrix is only useful if it is attached to something that changes, usually training or a promotion request.

Three things break at once without it. Nobody can answer "show me every competency requirement we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per competency requirement fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is under an hour of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A scale-tier system: build it when the business already runs on its own data rather than around it.

**What it does not do:** assess or certify competence.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** Which roles need a competency model?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - define a small set of levels and attach them to roles, then link the assessment result to the skill gap record.
4. **Build only on request** - CSV, SQL DDL, JSON Schema, a Notion mapping or an Excel workbook, data only.

The intended workflow is: Roles → Competencies → Level expectations → Assessment → Gap and training link

## Frequently asked questions

### What is the difference between competency matrix and a spreadsheet?

A spreadsheet is a container. Competency Matrix is a defined set of 9 fields, a known owner and a stated review rhythm, which is what makes the data trustworthy. The skill emits the same field list as CSV, SQL and JSON Schema so the structure survives the move out of the sheet.

### What fields does a competency matrix system usually include?

At minimum Competency, Category, Job Title, Grade Level. A complete version also covers Expected Level, Description, Assessment Method, Linked Skill Area. This template ships all 9, with types fixed rather than guessed.

### Do I need competency matrix if my team is small?

Usually yes, and earlier than people expect. Competency Matrix is a scale-tier system. The deciding question is not headcount, it is whether anyone can answer "show me every competency requirement we have" without checking with a person first.

### What does this system not do?

- Empty template only. It does not compute payroll, tax, leave balances or KPIs.

## SQL reference

```sql
CREATE TABLE competency_matrix (
  competency VARCHAR(255),
  category VARCHAR(100) NOT NULL,
  job_title VARCHAR(255),
  grade_level VARCHAR(100) NOT NULL,
  expected_level VARCHAR(100) NOT NULL,
  description TEXT,
  assessment_method VARCHAR(255),
  linked_skill_area VARCHAR(255),  -- relation -> target record
  competency_id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
