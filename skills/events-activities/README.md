**Events & Activities** - an events register records each company event with its owner, date, budget, sign-ups and what happened afterwards. Instead of a spreadsheet only one person understands, each event becomes a row with a named owner, a status and a review rhythm. 20 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per event, 20 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 20 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Event Name`; `Event Type`; `Date`; `Start Time`.
- `End Time`; `Venue or Link`; `Organizer`; `Department`.
- Plus 12 more: `Audience`, `Budget`, `Actual Cost`, `Currency`, `RSVP Count`, `Attended Count` and 6 more.

Field types break down as 1 auto ID, 7 text, 1 long text, 2 select, 4 number, 2 currency, 1 date, 1 web link and 1 relation. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Event budgets are approved one at a time and the total is never visible.

That is the argument for events and activities: events are planned in chat and lost by the week of. A single event record with an owner is the minimum that survives.

Three things break at once without it. Nobody can answer "show me every event we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per event fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is a couple of hours of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A growth-tier system: worth adding once headcount or volume makes manual tracking unreliable.

**What it does not do:** book venues, send invitations or process payments.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** What is the next event?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - one record per event with an owner, a date and a sign-up count, and a budget line only for events that have one.
4. **Build only on request** - CSV, SQL DDL, JSON Schema and a Notion mapping, data only.

The intended workflow is: Event listed → Sign-ups → Budget → Run → Feedback captured

## SQL reference

```sql
CREATE TABLE events_activities (
  event_name VARCHAR(255),
  event_type VARCHAR(100) NOT NULL,
  date DATE NOT NULL,
  start_time VARCHAR(255),
  end_time VARCHAR(255),
  venue_or_link TEXT,
  organizer VARCHAR(255),
  department VARCHAR(255),
  audience VARCHAR(255),
  budget NUMERIC(14,2) NOT NULL,
  actual_cost NUMERIC(14,2) NOT NULL,
  currency VARCHAR(255),
  rsvp_count NUMERIC NOT NULL,
  attended_count NUMERIC NOT NULL,
  attendance NUMERIC NOT NULL,
  feedback_score NUMERIC NOT NULL,
  linked_calendar_entry VARCHAR(255),  -- relation -> target record
  status VARCHAR(100) NOT NULL,
  notes TEXT,
  event_id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_events_activities_status ON events_activities (status);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
