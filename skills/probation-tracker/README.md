**Probation Tracker** - a probation tracker schedules the 30, 60 and 90 day reviews against fixed criteria, so a new hire’s early months are decided on evidence. Instead of a spreadsheet only one person understands, each probation review becomes a row with a named owner, a status and a review rhythm. 19 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per probation review, 19 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 19 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Probation Record`; `30-Day Review Date`; `30-Day Score`; `60-Day Review Date`.
- `60-Day Score`; `90-Day Review Date`; `90-Day Score`; `Confirmation Letter Issued`.
- Plus 11 more: `Department`, `Employee Name`, `End Date`, `Manager`, `Mentor / Buddy`, `Milestones Met` and 5 more.

Field types break down as 1 auto ID, 4 text, 1 long text, 1 select, 2 checkbox, 4 number, 5 date and 1 relation. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Probation passes or fails on whoever remembered to have the conversation.

That is the argument for probation tracker: probation reviews get missed because nobody owns the date. A tracker that surfaces the next review is the whole control.

Three things break at once without it. Nobody can answer "show me every probation review we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per probation review fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is a couple of hours of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A growth-tier system: worth adding once headcount or volume makes manual tracking unreliable.

**What it does not do:** decide employment outcomes or provide legal guidance.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** How long is the probation period?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - one record per person with the start date, review dates and the confirmation decision. Keep the criteria attached to the record.
4. **Build only on request** - CSV, SQL DDL, JSON Schema, a Notion mapping or an Excel workbook, data only.

The intended workflow is: Enrolment → First review → Mid review → Final review → Confirmed or extended

## Frequently asked questions

### What is the difference between probation tracker and a spreadsheet?

A spreadsheet is a container. Probation Tracker is a defined set of 19 fields, a known owner and a stated review rhythm, which is what makes the data trustworthy. The skill emits the same field list as CSV, SQL and JSON Schema so the structure survives the move out of the sheet.

### What fields does a probation tracker system usually include?

At minimum Probation Record, 30-Day Review Date, 30-Day Score, 60-Day Review Date. A complete version also covers 60-Day Score, 90-Day Review Date, 90-Day Score, Confirmation Letter Issued. This template ships all 19, with types fixed rather than guessed.

  department VARCHAR(255),

  manager VARCHAR(255),
  mentor_buddy VARCHAR(255),  -- relation -> target record

CREATE INDEX idx_probation_tracker_status ON probation_tracker (status);

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
