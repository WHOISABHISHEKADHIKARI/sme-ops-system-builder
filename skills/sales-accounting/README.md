## What it is

Sales orders, delivery challans, invoices and the receivables they create

## When to use it

- sales accounting
- sales invoice register
- customer billing and receivable tracker
- sales vat register log

## How it starts

Opens with one question, then asks only what is still missing - one per message.

> **Q:** How are sales invoices raised today?

- **Volume** - How many invoices a month? / How many customers?
- **Documents** - Sales order and challan every time? / Or invoice only?
- **Taxes and credit** - VAT charged? / TDS deducted by customers? / Discounts given? / How many sales are on credit? / Standard credit period? / Who follows up?
- **Current process** - Tracked now? / Software or sheet? / What gets missed?
- **Outcome** - What do you need? / A sales register, an aging view or both?

**Recommended approach:** One sales record per invoice, holding the order, challan and source document as relations, the full tax breakdown, and - where the sale is on credit - the due date, the debtor ledger and the outstanding balance - five steps: prepare documents, issue the invoice, update the Sales VAT Register, record in software, confirm the debtor ledger.

**Workflow:** Documents prepared (where used) → Invoice issued → VAT register updated (where VAT applies) → Recorded → Receivable confirmed against the debtor ledger

Artifacts are built only after the user asks for them.

## Fields (33)

```
Sales Number, Customer, Customer PAN/VAT, Sales Order, Delivery Challan, Invoice Number, Invoice Date, Item Description, Quantity, UOM, Rate, Gross Amount, Discount, Taxable Value, VAT Rate %, VAT Amount, TDS Rate %, TDS Amount, Invoice Total, Net Receivable, Credit Terms (Days), Due Date, Payment Status, Aging Status, Amount Received, Balance, Ledger Account, Source Document, VAT Register Updated, Entry Verified, Prepared By, Notes, Sales ID
```

One row is one invoice with a single line item. `VAT Rate %`, `VAT Amount`, `TDS Rate %`,
`TDS Amount`, `Credit Terms (Days)` and `Due Date` are optional - set them only from a
confirmed answer. `Payment Status` and `Aging Status` are separate on purpose.

## SQL setup

```sql
-- PostgreSQL-flavoured DDL. created_at/updated_at are database-maintained.
CREATE TABLE sales_accounting (
  sales_number VARCHAR(255),
  customer VARCHAR(255),
  customer_pan_vat VARCHAR(255),
  sales_order VARCHAR(255),  -- relation -> sales order database
  delivery_challan VARCHAR(255),  -- relation -> delivery challan database
  invoice_number VARCHAR(255),
  invoice_date DATE NOT NULL,
  item_description VARCHAR(255),
  quantity NUMERIC NOT NULL,
  uom VARCHAR(100) NOT NULL,
  rate NUMERIC(14,2) NOT NULL,
  gross_amount NUMERIC(14,2) NOT NULL,
  discount NUMERIC(14,2) NOT NULL,
  taxable_value NUMERIC(14,2) NOT NULL,
  vat_rate NUMERIC,
  vat_amount NUMERIC(14,2),
  tds_rate NUMERIC,
  tds_amount NUMERIC(14,2),
  invoice_total NUMERIC(14,2) NOT NULL,
  net_receivable NUMERIC(14,2) NOT NULL,
  credit_terms_days NUMERIC,
  due_date DATE,
  payment_status VARCHAR(100) NOT NULL,
  aging_status VARCHAR(100) NOT NULL,
  amount_received NUMERIC(14,2) NOT NULL,
  balance NUMERIC(14,2) NOT NULL,
  ledger_account VARCHAR(255),
  source_document VARCHAR(255),  -- relation -> source document register
  vat_register_updated VARCHAR(100) NOT NULL,

  prepared_by VARCHAR(255),
  notes TEXT,
  sales_id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT NOW(),
```

## Frequently asked questions

### What is the difference between sales accounting and a spreadsheet?

A spreadsheet is a container. Sales Accounting is a defined set of 33 fields with a named owner and a review rhythm, one row per invoice, so the tax breakdown and the outstanding balance stay attached to the sale they came from. The same field list is emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four artifacts cannot drift apart.

### What fields does a sales accounting system usually include?

At minimum Customer, Invoice Number, Invoice Date, Invoice Total, Net Receivable. A complete version also covers Sales Order, Delivery Challan, Source Document, VAT Amount, TDS Amount, Credit Terms (Days), Due Date, Receivable Status, Amount Received, Balance. This template ships all 32, with the three document links kept as relations rather than free text.

### Do I need sales accounting if my team is small?

Yes - it is a starter-tier system, and most small teams need it from the first invoice, because receivables are the first thing that goes missing. The deciding question is not headcount, it is whether anyone can answer "who owes us, how much, and by when" without checking with a person first.

### What does this system not do?

Empty template only, and it raises nothing. It does not raise or send invoices, collect money, or file the VAT return. It has no automation, reminders or sync, its Notion relation columns stay empty until the target database is imported, and its Select options are only a starting set to rename.

### How does it fit with other systems?

It links rather than duplicates. Related modules: `source-document-filing` files the invoice with its order, challan and other support, `receipt-accounting` clears the receivable carried in Net Receivable and Balance, `credit-cycle-analysis` ages the outstanding balances this module produces, and `party-ledger-reconciliation` reconciles the debtor ledger against this register. Each keeps its own table and joins on an ID.

## Troubleshooting

- Columns show as Text after import - expected, apply the mapping table.
- Relation column stays empty - the target database must exist first.
- Dates sort as text - convert the column to Date after import.
