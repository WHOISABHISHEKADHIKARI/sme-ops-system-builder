**Performance Management** - a performance management system records structured reviews against agreed goals, with evidence, ratings and the actions that follow. Instead of a spreadsheet only one person understands, each review becomes a row with a named owner, a status and a review rhythm. 22 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per review, 22 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 22 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Review Title`; `Areas for Improvement`; `Behaviour Score`; `Department`.
- `Development Plan`; `Due Date`; `Employee Name`; `Increment Recommended`.
- Plus 14 more: `KPI Score`, `Notes`, `OKR Score`, `Overall Rating`, `PIP Required`, `Promotion Eligible` and 8 more.

Field types break down as 1 auto ID, 9 text, 1 long text, 3 select, 3 checkbox, 3 number and 2 date. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Reviews happen when the calendar forces them, and the notes end up in each manager’s own document.

That is the argument for performance management: reviews become paperwork when the review duplicates data you already track. Reference the KPI and OKR records instead of re-entering them.

Three things break at once without it. Nobody can answer "show me every review we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per review fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is a couple of hours of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A growth-tier system: worth adding once headcount or volume makes manual tracking unreliable.

**What it does not do:** make promotion or pay decisions, and carries no legal standing on its own.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** How often do you review people?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - build the review form around goals and behaviours already tracked elsewhere, and store the record per cycle.
4. **Build only on request** - CSV, SQL DDL, JSON Schema, a Notion mapping or an Excel workbook, data only.

The intended workflow is: Review cycle → Self input → Manager review → Discussion → Record and actions

## Frequently asked questions

### What is the difference between performance management and a spreadsheet?

A spreadsheet is a container. Performance Management is a defined set of 22 fields, a known owner and a stated review rhythm, which is what makes the data trustworthy. The skill emits the same field list as CSV, SQL and JSON Schema so the structure survives the move out of the sheet.

### What fields does a performance management system usually include?

At minimum Review Title, Areas for Improvement, Behaviour Score, Department. A complete version also covers Development Plan, Due Date, Employee Name, Increment Recommended. This template ships all 22, with types fixed rather than guessed.

### Do I need performance management if my team is small?

Usually yes, and earlier than people expect. Performance Management is a growth-tier system. The deciding question is not headcount, it is whether anyone can answer "show me every review we have" without checking with a person first.

### What does this system not do?

- Empty template only. It does not compute payroll, tax, leave balances or KPIs.

## When to involve a professional

Performance Management touches decisions with legal, financial or employment consequences. Use the template to organise what you already decided, and confirm the underlying rules with a qualified adviser in your jurisdiction before you rely on them. Local leave, tax, payroll and disciplinary rules differ by country and this page cannot settle them.

## SQL reference

```sql
CREATE TABLE performance_management (
  review_title VARCHAR(255),
  areas_for_improvement VARCHAR(255),
  behaviour_score NUMERIC NOT NULL,
  department VARCHAR(255),
  development_plan VARCHAR(255),
  due_date DATE NOT NULL,
  employee_name VARCHAR(255),
  increment_recommended BOOLEAN NOT NULL,
  kpi_score NUMERIC NOT NULL,
  notes TEXT,
  okr_score NUMERIC NOT NULL,
  overall_rating VARCHAR(100) NOT NULL,
  pip_required BOOLEAN NOT NULL,
  promotion_eligible BOOLEAN NOT NULL,

CREATE INDEX idx_performance_management_status ON performance_management (status);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
