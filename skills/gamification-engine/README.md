**Gamification Engine** - a gamification engine records points, badges and recognition events, so participation is visible without turning work into a contest. Instead of a spreadsheet only one person understands, each award becomes a row with a named owner, a status and a review rhythm. 11 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per award, 11 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 11 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Player`; `Employee Name`; `Department`; `Points Balance`.
- `Points This Month`; `Level`; `Badges`; `Source Module`.
- Plus 3 more: `Last Updated`, `Notes`, `Player ID`.

Field types break down as 1 auto ID, 5 text, 1 long text, 1 select, 2 number and 1 date. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Recognition happens in a chat and leaves no record, so the same people get thanked repeatedly.

That is the argument for gamification engine: gamification fails when the points do not connect to something people care about. Start with one behaviour and a monthly reset.

Three things break at once without it. Nobody can answer "show me every award we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per award fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is under an hour of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A scale-tier system: build it when the business already runs on its own data rather than around it.

**What it does not do:** run recognition programmes or deliver rewards.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** What behaviour are you trying to change?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - use points for the behaviour you want and nothing else. A leaderboard only works if most people can appear on it.
4. **Build only on request** - CSV, SQL DDL, JSON Schema, a Notion mapping or an Excel workbook, data only.

The intended workflow is: Behaviour → Award points → Balance → Leaderboard or summary → Review

## Frequently asked questions

### What is the difference between gamification engine and a spreadsheet?

A spreadsheet is a container. Gamification Engine is a defined set of 11 fields, a known owner and a stated review rhythm, which is what makes the data trustworthy. The skill emits the same field list as CSV, SQL and JSON Schema so the structure survives the move out of the sheet.

At minimum Player, Employee Name, Department, Points Balance. A complete version also covers Points This Month, Level, Badges, Source Module. This template ships all 11, with types fixed rather than guessed.

## SQL reference

```sql
CREATE TABLE gamification_engine (
  player VARCHAR(255),
  employee_name VARCHAR(255),
  department VARCHAR(255),
  points_balance NUMERIC NOT NULL,
  points_this_month NUMERIC NOT NULL,
  level VARCHAR(100) NOT NULL,
  badges VARCHAR(255),
  source_module VARCHAR(255),
  last_updated DATE NOT NULL,
  notes TEXT,
  player_id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
