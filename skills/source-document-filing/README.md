## What it is

Indexed register of every supporting document, linked to the entry it supports

## When to use it

- source document filing
- document index register
- bill and voucher filing tracker
- supporting document audit trail

## How it starts

Opens with one question, then asks only what is still missing - one per message.

> **Q:** Which document types do you currently file?

- **Documents** - Which types? / Purchase, sales, payroll? / How many a month?
- **Filing** - Physical, digital or both? / How are files named and sorted?
- **Indexing** - Any index or reference in use? / By period, by party or both?
- **Retention** - How long to keep? / Any legal retention rules? / Who disposes?
- **Outcome** - What do you need? / A register, a reindex plan or both?

**Recommended approach:** One register row per document, with a reference key built as `period/party` (for example `2026/08/BLUEPEAK`) so retrieval is by month and by party, and relation links to the voucher and the transaction it supports.

**Workflow:** Document received → Referenced and indexed → Filed → Linked to entry → Verified

Artifacts are built only after the user asks for them.

## SQL setup

```sql
CREATE TABLE source_document_filing (
  document_reference VARCHAR(255),
  document_type VARCHAR(100) NOT NULL,
  document_number VARCHAR(255),
  document_date DATE NOT NULL,
  party_name VARCHAR(255),
  party_pan_vat VARCHAR(255),
  amount NUMERIC(14,2) NOT NULL,
  currency VARCHAR(255),
  tax_amount NUMERIC(14,2),
  tds_amount NUMERIC(14,2),
  source_department VARCHAR(100) NOT NULL,
  index_key VARCHAR(255),
```

## Frequently asked questions

### What is the difference between source document and filing and a spreadsheet?

A spreadsheet is a container. Source Document & Filing is a defined set of 22 fields with a named owner and a review rhythm, one row per document indexed by a `period/party` reference key, so the challan behind a bill is found without walking a folder. The same field list is emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four artifacts cannot drift apart.

### What fields does a source document and filing system usually include?

At minimum Document Reference, Document Type, Document Number, Document Date, Party Name. A complete version also covers Index Key, Storage Location, Retention Period, Linked Voucher, Linked Transaction, Document Availability, Verification Status, Verified By. This template ships all 22, with the two links kept as relations rather than free text.

### Do I need source document and filing if my team is small?

Not while the filing cabinet still works - it is a growth-tier system, and a small team can find a bill by memory. The deciding question is whether anyone can answer "show me the challan and PO behind invoice 214" without checking with a person first, which is exactly what an auditor or a new hire asks.

### What does this system not do?

Empty template only, and it stores no files. It does not scan, store or digitise documents, and it does not set retention policy for the business - Retention Period is a field you fill in, not a rule the template enforces. It has no automation, reminders or sync, and its Select options are only a starting set to rename.

### How does it fit with other systems?

It links rather than duplicates. Related modules: `purchase-accounting` and `sales-accounting` for the entries these documents support, `payment-accounting` for the payment entries, and `audit-preparation`, which reads this register to answer evidence requests. Each keeps its own table and joins on an ID, so the register outlives any one of them.

## Troubleshooting

- Columns show as Text after import - expected, apply the mapping table.
- Relation column stays empty - the target database must exist first.
- Dates sort as text - convert the column to Date after import.
