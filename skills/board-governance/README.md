**Board & Governance** - a board record captures each meeting, the decisions taken, the actions they created and the risks on the register, with owners and dates. Instead of a spreadsheet only one person understands, each board item becomes a row with a named owner, a status and a review rhythm. 16 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per board item, 16 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 16 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Board Item`; `Item Type`; `Meeting Date`; `Agenda`.
- `Presented By`; `Decision`; `Resolution Number`; `Vote Result`.
- Plus 8 more: `Action Owner`, `Due Date`, `Risk Level`, `Linked Report`, `Documents`, `Confidential` and 2 more.

Field types break down as 1 auto ID, 8 text, 4 select, 2 date and 1 relation. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Board decisions are minuted in a document nobody can search a year later.

That is the argument for board and governance: governance records fail on lost actions rather than missing minutes. The action log is what the board actually needs.

Three things break at once without it. Nobody can answer "show me every board item we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per board item fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is under an hour of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A growth-tier system: worth adding once headcount or volume makes manual tracking unreliable.

**What it does not do:** provide legal or governance advice, and cannot replace company secretarial duties.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** How often does the board meet?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - keep meetings, papers and decisions as separate records joined by the meeting, and track actions to a due date and an owner.
4. **Build only on request** - CSV, SQL DDL, JSON Schema, a Notion mapping or an Excel workbook, data only.

The intended workflow is: Meeting scheduled → Papers circulated → Meeting held → Minutes recorded → Actions tracked

## SQL reference

```sql
CREATE TABLE board_governance (
  board_item VARCHAR(255),
  item_type VARCHAR(100) NOT NULL,
  meeting_date DATE NOT NULL,
  agenda VARCHAR(255),
  presented_by VARCHAR(255),
  decision VARCHAR(255),
  resolution_number VARCHAR(255),
  vote_result VARCHAR(255),
  action_owner VARCHAR(255),
  due_date DATE NOT NULL,
  risk_level VARCHAR(100) NOT NULL,
  linked_report VARCHAR(255),  -- relation -> target record
  documents VARCHAR(255),
  confidential VARCHAR(100) NOT NULL,
  status VARCHAR(100) NOT NULL,
  board_item_id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_board_governance_status ON board_governance (status);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
