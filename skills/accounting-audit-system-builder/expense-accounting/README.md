## What it is

Expenses booked to the right account, with the tax treatment and the document type recorded for each

## When to use it

- expense register
- petty expense sheet
- expense book with tax
- bill and voucher log

## How it starts

Opens with one question, then asks only what is still missing - one per message.

> **Q:** What is your biggest expense category this month?

- **Categories** - What do you spend on? / How many categories do you actually use? / Any fixed monthly bills?
- **Documents** - Do you get a bill for everything? / Which expenses never have one? / What is accepted instead?
- **Tax** - Is VAT/GST charged? / Is TDS deducted? / Who decides the rates?
- **Approvals** - Who approves an expense? / Who reviews the entry? / Any spending limits?
- **Outcome** - What do you need? / An expense register, a payment file or both?

**Recommended approach:** One expense row per bill or supporting document, carrying the nature of the expense, the document type, the account and the tax treatment on the same row.

**Workflow:** Nature identified → Document obtained → Payee verified → Tax treatment decided → Posted to account → Attached and reviewed

Artifacts are built only after the user asks for them.

## Frequently asked questions

### What is the difference between Expense Accounting and a spreadsheet?

A spreadsheet is a container. Expense Accounting is a defined set of 26 fields, a named owner and a booked-as-it-happens, reviewed-at-month-end rhythm, which is what makes the row defensible later. The same 26 fields are emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four cannot disagree and the tax treatment travels with the expense instead of living in someone's head.

### What fields does an expense accounting system usually include?

At minimum Expense Number, Expense Date, Category, Payee, Amount, Ledger Account, Approved By. A complete version also records the document side and the tax side: Bill/Invoice Number, Document Type, Internal Support Justified, Justification, VAT Rate %, VAT Amount, TDS Rate %, TDS Amount, Net Payable, Department, Source Document and Payment Reference. This template ships all 26, with types fixed rather than guessed.

### Do I need Expense Accounting if my team is small?

Yes. It is a starter-tier system, and most small teams need it from their first month, because the category, the document type and the tax treatment are the three things that turn an expense from an opinion into a record. The deciding question is not headcount, it is whether anyone can answer "what did we spend on professional fees last quarter, and which of those had a bill?" without checking with a person first.

### What does this system not do?

It ships an empty template and books nothing. It does not compute tax, post journal entries, approve anything or pay an invoice, and it does not file returns or give tax advice. It also does not decide whether an internal supporting document is acceptable in your case: internal support is only defensible where the transaction does not normally produce a formal invoice, and the tax authority's position is what settles it.

### How does it fit with other systems?

It links rather than duplicates. Related modules: `payment-accounting`, `source-document-filing`, `tds-booking-payment`, `salary-wage-accounting`, `day-book`. Each keeps its own table and joins on an ID, so the stored bill lives in one place, the net figure is paid from another and the deduction carries on into the statutory register without being retyped. `Source Document` and `Payment Reference` are the two relation fields that hold this together.

## Troubleshooting

- Columns show as Text after import - expected, apply the mapping table.
- Relation column stays empty - the target database must exist first.
- Dates sort as text - convert the column to Date after import.
- Select values rejected on import - add the options listed in the mapping table first.
