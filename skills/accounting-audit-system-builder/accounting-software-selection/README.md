## What it is

Scored evaluation of shortlisted accounting packages before one is chosen

## When to use it

- accounting software selection
- accounting and erp software comparison
- vendor demo evaluation sheet
- accounting package quotation tracker

## How it starts

Opens with one question, then asks only what is still missing - one per message.

> **Q:** Which accounting or ERP packages are currently on your shortlist?

- **Business** - What does the business do? / Trading, manufacturing, services or a mix? / How many people? / How many transactions a month? / How many companies, branches, warehouses?
- **Accounting** - General ledger, receivables, payables, bank reconciliation, fixed assets, budgeting, cost centres? / Multi-company accounting needed?
- **Trading and Inventory** - Purchasing, sales, returns, stock, warehouses, valuation, customer credit limits, supplier management?
- **Manufacturing and Services** - Bill of materials, work orders, production planning, consumption, finished goods, production costing, wastage, scrap, batch or lot tracking, subcontracting? / Service invoicing, projects, job costing, timesheets, profitability?
- **Nepal and Platform** - VAT, PAN, TDS, IRD reporting, e-billing or CBMS, Nepal fiscal year and BS/AD dates, payroll and SSF? / Permissions, approvals, maker-checker, cloud or on-premise, backup, security, API, migration, local support, training?

**Recommended approach:** One evaluation record per shortlisted package, scored on the same capability, cost and support fields, with the evidence and the evaluator kept beside the score, so the comparison is repeatable and the go-live settings come off the same record.

**Workflow:** Requirements → Candidate Shortlist → Vendor Demo → Standardized Tests → Stakeholder Evaluation → Cost/TCO Review → Business Decision → Configuration → Migration → Training → Go-live

Artifacts are built only after the user asks for them.

## Owner and cadence

- Owner: whoever runs the evaluation, with one named person per candidate record.
- Cadence: review the scorecard after every demo and before the renewal date, not on a fixed date.
- Data: keep the example row until the first real record replaces it, and keep one record per candidate.

## Relations

No relation fields. Standalone table.

## Frequently asked questions

### What is the difference between accounting software selection and a spreadsheet?

A spreadsheet is a container. Accounting Software Selection is a defined set of 57 fields with a named owner and a review rhythm, one row per shortlisted package scored on the same capability, cost and support fields, which is what makes the comparison repeatable. The same field list is emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four artifacts cannot drift apart.

### What fields does an accounting software selection system usually include?

At minimum Evaluation ID, Software, Vendor, Selection Decision, First-Year Cost and Three-Year TCO. A complete version also covers Deployment Type, Accounting Coverage, VAT Support, TDS Support, Payroll/SSF Support, E-Billing/CBMS Support, Demo Test Result, Licence Cost, Implementation Cost, Customization Cost, Training Cost, Annual Renewal, Deal-breaker, Rejection Reason, Evaluated By and Evidence/Source. This template ships all 57, with the four decision fields kept separate so a score can never hide a failed Must-have.

### Do I need accounting software selection if my team is small?

Not on day one - it is a growth-tier system, and a small team usually gets further running the incumbent package until a renewal or a payroll requirement forces the question. The deciding question is whether anyone can answer "which package on the shortlist actually covers payroll, and what does it cost over three years" without checking with a person first.

### What does this system not do?

Empty template only, and it computes nothing. It does not score the packages for you, run the demos, verify a vendor's claims or turn a quotation into a TCO. It never chooses the package: it records the decision the business makes in Selection Decision, with Rejection Reason and Deal-breaker beside it. It cannot verify Nepal IRD, VAT, TDS, e-billing, CBMS or SSF handling - those stay Untested until the business holds current evidence. It has no automation, reminders or sync, and it does not procure licences or give vendor or legal advice.

### How does it fit with other systems?

It links rather than duplicates. Related modules: `purchase-accounting` and `sales-accounting` for the entry flows the chosen package has to support, `salary-wage-accounting` for the payroll module being evaluated, `tds-booking-payment` for withholding, and `monthly-closing-statements` for the reporting output. Each keeps its own table and joins on an ID, so you can replace one without breaking the rest.

## Troubleshooting

- Columns show as Text after import - expected, apply the mapping table.
- A capability you have not checked yet - leave it Untested, never guess a score.
- A price nobody has quoted - record Unknown and keep the cost field empty until the quotation arrives.
- Dates sort as text - convert the column to Date after import.
