## What it is

Scored evaluation of shortlisted accounting packages before one is chosen

## When to use it

- accounting software selection
- software comparison sheet
- vendor evaluation record
- accounting package quotation tracker

## How it starts

Opens with one question, then asks only what is still missing - one per message.

> **Q:** Which accounting packages are on your shortlist?

- **Business** - What does the business do? / How many people? / How many transactions a month?
- **Requirements** - Inventory needed? / VAT, TDS, payroll? / Which reports must come out?
- **Shortlist** - How many packages? / Demos seen or not yet? / Who evaluates?
- **Costs** - Quotations in hand? / Licence plus implementation? / Annual renewal known?
- **Outcome** - What do you need? / A comparison register, a go-live checklist or both?

**Recommended approach:** One evaluation record per shortlisted package, scored on the same coverage, cost and support fields so the comparison is repeatable, plus a go-live configuration checklist built from the same record.

**Workflow:** Requirements listed → Package shortlisted → Demo tested → Scored → Recommended → Configured → Go-live

Artifacts are built only after the user asks for them.

## Frequently asked questions

### What is the difference between accounting software selection and a spreadsheet?

A spreadsheet is a container. Accounting Software Selection is a defined set of 26 fields with a named owner and a review rhythm, one row per shortlisted package scored on the same coverage, cost and support fields, which is what makes the comparison repeatable. The same field list is emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four artifacts cannot drift apart.

### What fields does an accounting software selection system usually include?

At minimum Software, Vendor, Total Cost, Recommendation. A complete version also covers Deployment Type, Accounting Coverage, Payroll Support, TDS Support, Quotation Amount, Implementation Fee, Evaluated By. This template ships all 26, with types fixed rather than guessed.

### Do I need accounting software selection if my team is small?

Not on day one - it is a growth-tier system, and a small team usually gets further running the incumbent package until a renewal or a payroll requirement forces the question. The deciding question is whether anyone can answer "which package on the shortlist actually covers payroll, and what does it cost over three years" without checking with a person first.

### What does this system not do?

Empty template only, and it computes nothing. It does not score the packages for you, test the software or compute TCO. It does not choose the software or configure a live system - chart of accounts, tax configuration, users, inventory, opening balances and the test entry are a checklist you carry out with the vendor. It has no automation, reminders or sync, and it does not procure licences or give vendor or legal advice.

### How does it fit with other systems?

It links rather than duplicates. Related modules: `purchase-accounting` and `sales-accounting` for the entry flows the chosen package has to support, `salary-wage-accounting` for the payroll module being evaluated, `tds-booking-payment` for withholding, and `monthly-closing-statements` for the reporting output. Each keeps its own table and joins on an ID, so you can replace one without breaking the rest.
