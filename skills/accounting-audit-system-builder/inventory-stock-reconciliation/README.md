## What it is

One record per item counted, carrying the book quantity, the physical quantity, the variance, the investigated reason and the authorised adjustment

## When to use it

- physical stock count
- stock variance investigation
- stock adjustment register
- inventory shrinkage tracker
- cycle count sheet

## How it starts

Opens with one question, then asks only what is still missing - one per message.

> **Q:** How many items do you hold, and when did you last count them physically?

The two halves are tracked independently. `20 to 50` records the item count and leaves the
last physical count date unknown.

- **Stock** - What do you hold? / Raw material, finished goods or both? / How many locations?
- **Count** - When did you last count? / Full count or cycle count? / How often? / **Who counts?** / **Who verifies?** - asked as two separate questions
- **Differences** - What gets investigated? / Who approves an adjustment? / Any threshold to escalate?
- **Current process** - Counted at all? / Sheet or accounting package? / What gets missed?
- **Outcome** - A reconciliation record, a count sheet or both? / Which artifacts do you want?

`yes` is not an answer to "a full count or a cycle count?". That question is re-asked as an
explicit choice rather than guessed at, and nothing nobody has told you is filled with a
plausible value. Unknown is never recorded as zero.

**Recommended approach:** One reconciliation record per item counted, carrying the book quantity, the physical quantity, the variance, the investigated reason and the authorised adjustment, with the count sheet filed against the same record so the count can be repeated next time.

**Workflow:** Count planned → Items counted → Compared with books → Variance investigated → Adjustment authorised → Adjustment booked → Reconciliation filed

Artifacts are built only after you ask, and only the ones you ask for. What you get is an
empty template: a CSV header row with no data row, DDL with no sample records, and a schema
with no example values.

## SQL setup

```sql
CREATE TABLE inventory_stock_reconciliation (
  reconciliation_number VARCHAR(255),
  count_date DATE NOT NULL,
  item_code VARCHAR(255),
  item_name VARCHAR(255),
  category VARCHAR(100) NOT NULL,
  uom VARCHAR(100) NOT NULL,
  location_warehouse VARCHAR(255),
  book_quantity NUMERIC,
  physical_quantity NUMERIC,
  variance_quantity NUMERIC,
  unit_rate NUMERIC(14,2) NOT NULL,
  variance_value NUMERIC(14,2) NOT NULL,
  variance_reason VARCHAR(100) NOT NULL,
  damaged_quantity NUMERIC,
  expired_quantity NUMERIC,
  slow_moving_flag VARCHAR(100),
  unrecorded_purchases NUMERIC,
  unrecorded_issues NUMERIC,
  investigation_notes TEXT,
  adjustment_entry VARCHAR(255),
  adjustment_date DATE,
  approved_by VARCHAR(255),
  counted_by VARCHAR(255),
  verified_by VARCHAR(255),
  count_frequency VARCHAR(100) NOT NULL,
  status VARCHAR(100) NOT NULL,
  notes TEXT,
  inventory_reconciliation_id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW(),
  CONSTRAINT chk_variance_matches_count CHECK (variance_quantity IS NULL OR physical_quantity IS NULL OR book_quantity IS NULL OR variance_quantity = physical_quantity - book_quantity),
  CONSTRAINT chk_unit_rate_non_negative CHECK (unit_rate IS NULL OR unit_rate >= 0)
);

CREATE INDEX idx_inventory_stock_reconciliation_count_date ON inventory_stock_reconciliation (count_date);
CREATE INDEX idx_inventory_stock_reconciliation_status ON inventory_stock_reconciliation (status);
```

`Inventory Reconciliation ID`, `created_at` and `updated_at` are technical metadata. The DDL
carries no sample records and no invented defaults, and no `FOREIGN KEY`, because no target
table is part of this artifact set.

## Owner and cadence

- Owner: whoever runs this process day to day.
- Cadence: review the schema when the process changes, not on a fixed date.
- Data: the shipped CSV is an empty template - a header row and nothing else. The row shown
  in the skill is a labelled placeholder, not a record.
- Count: periodic by design - monthly where volume or value is high, at minimum
  quarterly, and the frequency belongs in the record rather than in someone's memory.
- Adjustment: no entry without a named approver and a recorded reason. A variance with no
  investigated reason stays unresolved and the record does not reach `Done`.
- Roles: `Counted By`, `Verified By` and `Approved By` are three people doing three jobs.
  None is filled in from another, and an unanswered one stays blank rather than borrowing a
  name from a neighbouring column.

## Relations

No relation fields. Standalone table - nothing here points at a database that does not exist.
If you want the count sheet or the stock movement attached, add the link field deliberately
as `VARCHAR(255)` with a comment in SQL, and as `Relation` in Notion only once the target
database is actually imported.

## Troubleshooting

- Columns show as Text after import - expected, apply the mapping table.
- Dates sort as text - convert the column to Date after import.
- Variance will not compute - `Variance Quantity = Physical Quantity - Book Quantity`, valued
  at the unit rate on the same row. A row that does not tie is marked for review, never
  corrected to force a tie-out.
- A row sits at `In progress` for weeks - the investigated reason or the named approver is
  missing; that is the gate, not a status problem.
- A variance reason was filled in from the dropdown - the reason is somebody's judgement, not
  a menu. `Under Investigation` is the honest value until someone has looked.
- `Verified By` is blank and looks awkward - ask the question. It is not the same person as
  the counter or the approver unless you say so.

## Frequently asked questions

### What is the difference between inventory stock reconciliation and a spreadsheet?

A spreadsheet holds a count and a total. Inventory / Stock Reconciliation is a defined set of 28 fields where the count, the book quantity, the variance, the reason and the approver all sit on one row, with a named counter and a named verifier beside them. The same fields are emitted as CSV, SQL, JSON Schema and a Notion mapping, from one list, in one order. A sheet tells you stock is short; this tells you who signed the write-off off and on what grounds - and it ships empty, so the first number in it is one somebody actually counted.

### What fields does an inventory stock reconciliation system usually include?

At minimum Reconciliation Number, Count Date, Item Code, Book Quantity, Physical Quantity, Variance Quantity. A complete version also carries Variance Value, Variance Reason, Damaged Quantity, Expired Quantity, Unrecorded Purchases, Unrecorded Issues, Adjustment Entry, Adjustment Date, Approved By, Counted By, Verified By and Count Frequency, because a difference is only worth anything once someone has explained it and someone else has approved it. This template ships all 28, in that order, in all four artifacts.

### Do I need inventory stock reconciliation if my team is small?

Yes - a growth-tier system, and any team holding physical stock needs it before the first close rather than after the shrinkage has shown up in the accounts. The deciding question is whether anyone can answer "how much did we count last quarter, and who approved the difference" without checking with a person. Counting is periodic by design: monthly where volume or value is high, quarterly at minimum, and the frequency belongs in the record rather than in someone's memory.

### What does this system not do?

It ships an empty template and computes or posts nothing. It does not count the stock, change stock, value the inventory or post the journal entry - the variance arithmetic belongs to the accounting package. It cannot tell theft from a mis-pick from an unrecorded issue, and it does not decide whether a discrepancy is misconduct; that call belongs to a person who knows the operation, and the row only carries the reason they gave. It does not set the valuation method, the reorder point or the costing policy, and it states no tax treatment. It never invents a name, a date, a quantity, a price, a location, an approval, a variance reason or a transaction reference to fill a gap - a blank is a correct answer.

### How does it fit with other systems?

It links rather than duplicates. Related modules: `purchase-accounting`, `sales-accounting`, `day-book` and `expense-accounting`. Each keeps its own table and joins on an ID, so unrecorded purchases and unrecorded issues get traced back to the transaction that caused them instead of being netted off here, and damaged or expired stock has somewhere to land once it is written off. This table declares no relation fields of its own.
