**Time Tracking** - a time tracker records hours against work and a project, which is what turns an hourly rate into a real invoice. Instead of a spreadsheet only one person understands, each time entry becomes a row with a named owner, a status and a review rhythm. 20 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per time entry, 20 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 20 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Time Entry`; `Approver`; `Billable`; `Billable Rate (per hour)`.
- `Currency`; `Billable Amount`; `Invoice`; `Date`.
- Plus 12 more: `Department`, `Employee Name`, `Hours Logged`, `Month`, `Notes`, `Project` and 6 more.

Field types break down as 1 auto ID, 9 text, 2 long text, 2 select, 2 number, 2 currency, 1 date and 1 relation. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Hours are remembered at the end of the month, and the client has usually been invoiced already.

That is the argument for time tracking: time data is only worth collecting if something uses it. Billing is the strongest reason; if there is none, keep the entry minimal.

Three things break at once without it. Nobody can answer "show me every time entry we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per time entry fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is a couple of hours of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A starter-tier system: most small teams need it from day one.

**What it does not do:** send invoices, pay people or monitor anyone continuously.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** Do you bill by the hour?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - collect time by project, and connect billing to it only if you bill by the hour. Lock the period once it is invoiced.
4. **Build only on request** - CSV, SQL DDL, JSON Schema and a Notion mapping, data only.

The intended workflow is: Entry → Approval → Lock period → Invoice or cost view

## SQL reference

```sql
CREATE TABLE time_tracking (
  time_entry VARCHAR(255),
  approver VARCHAR(255),
  billable VARCHAR(255),  -- relation -> target record
  billable_rate_per_hour NUMERIC(14,2) NOT NULL,
  currency VARCHAR(255),
  billable_amount NUMERIC(14,2) NOT NULL,
  invoice VARCHAR(255),
  date DATE NOT NULL,
  department VARCHAR(255),
  employee_name VARCHAR(255),
  hours_logged NUMERIC NOT NULL,
  month VARCHAR(255),
  notes TEXT,
  project VARCHAR(255),
  client VARCHAR(255),
  status VARCHAR(100) NOT NULL,
  task_description TEXT,
  time_id SERIAL PRIMARY KEY,
  type VARCHAR(100) NOT NULL,
  week_number NUMERIC NOT NULL,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_time_tracking_status ON time_tracking (status);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
