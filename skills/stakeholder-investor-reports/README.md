**Stakeholder & Investor Reports** - a stakeholder report records what each audience is told, on what basis and on what date, so external numbers stay consistent. Instead of a spreadsheet only one person understands, each report becomes a row with a named owner, a status and a review rhythm. 10 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per report, 10 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 10 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Report Title`; `Stakeholder`; `Period`; `Prepared By`.
- `Approved By`; `Key Metrics`; `Send Date`; `Report Link`.
- Plus 2 more: `Status`, `Report ID`.

Field types break down as 1 auto ID, 6 text, 1 select, 1 date and 1 web link. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Different stakeholders receive slightly different numbers for the same period.

That is the argument for stakeholder and investor reports: investor reporting fails on version drift and unverified numbers. A fixed section list and a named verifier solve both.

Three things break at once without it. Nobody can answer "show me every report we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per report fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is under an hour of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A scale-tier system: build it when the business already runs on its own data rather than around it.

**What it does not do:** produce audited figures or provide investor or legal advice.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** Who needs the next stakeholder update?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - agree the sections once, then reuse them each period, and keep a check on who verified each number before it goes out.
4. **Build only on request** - CSV, SQL DDL, JSON Schema and a Notion mapping, data only.

The intended workflow is: Data gathered → Verified → Section drafted → Approved → Sent with a version marker

## SQL reference

```sql
CREATE TABLE stakeholder_investor_reports (
  report_title VARCHAR(255),
  stakeholder VARCHAR(255),
  period VARCHAR(255),
  prepared_by VARCHAR(255),
  approved_by VARCHAR(255),
  key_metrics VARCHAR(255),
  send_date DATE NOT NULL,
  report_link TEXT,
  status VARCHAR(100) NOT NULL,
  report_id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_stakeholder_investor_reports_status ON stakeholder_investor_reports (status);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
