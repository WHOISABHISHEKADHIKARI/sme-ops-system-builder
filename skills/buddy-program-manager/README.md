**Buddy Program Manager** - a buddy programme pairs each new joiner with a named colleague for a fixed period, and tracks the check-ins that make it work. Instead of a spreadsheet only one person understands, each pairing becomes a row with a named owner, a status and a review rhythm. 12 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per pairing, 12 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 12 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Buddy Pair`; `New Hire`; `Buddy`; `Department`.
- `Start Date`; `End Date`; `Check-ins Planned`; `Check-ins Done`.
- Plus 4 more: `Feedback Score`, `Status`, `Notes`, `Buddy ID`.

Field types break down as 1 auto ID, 2 text, 1 long text, 1 select, 3 number, 2 date and 2 relation. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

New joiners spend their first month not knowing who to ask.

That is the argument for buddy program manager: buddy programmes fail on load, not on matching. Three check-ins over 30 days is enough signal; more is admin nobody does.

Three things break at once without it. Nobody can answer "show me every pairing we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per pairing fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is under an hour of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A scale-tier system: build it when the business already runs on its own data rather than around it.

**What it does not do:** assign buddies automatically or send reminders without a connected tool.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** How many new joiners do you onboard a month?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - match buddies by department and timezone, then track a small number of check-ins. Do not build a scoring system for it.
4. **Build only on request** - CSV, SQL DDL, JSON Schema, a Notion mapping or an Excel workbook, data only.

The intended workflow is: New joiner → Buddy match → Check-ins → Feedback → Buddy recognition

## SQL reference

```sql
CREATE TABLE buddy_program_manager (
  buddy_pair VARCHAR(255),
  new_hire VARCHAR(255),  -- relation -> target record
  buddy VARCHAR(255),  -- relation -> target record
  department VARCHAR(255),
  start_date DATE NOT NULL,
  end_date DATE NOT NULL,
  check_ins_planned NUMERIC NOT NULL,
  check_ins_done NUMERIC NOT NULL,
  feedback_score NUMERIC NOT NULL,
  status VARCHAR(100) NOT NULL,
  notes TEXT,
  buddy_id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_buddy_program_manager_status ON buddy_program_manager (status);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
