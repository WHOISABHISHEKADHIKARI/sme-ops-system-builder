**Document Management System** - a document system records each document with its owner, its version, its location and its signature status, so the current copy is never in doubt. Instead of a spreadsheet only one person understands, each document becomes a row with a named owner, a status and a review rhythm. 13 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per document, 13 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 13 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Document Title`; `Document Type`; `Employee Name`; `Department`.
- `Uploaded By`; `Upload Date`; `Signature Required`; `Signed Date`.
- Plus 5 more: `Version`, `Storage Link`, `Confidentiality`, `Status`, `Document ID`.

Field types break down as 1 auto ID, 5 text, 3 select, 1 checkbox, 2 date and 1 web link. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Three versions of the same document exist and it is never clear which one is current.

That is the argument for document management system: document systems fail at versioning and ownership, not at storage. A naming rule plus one owner per document type is the practical fix.

Three things break at once without it. Nobody can answer "show me every document we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per document fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is under an hour of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A growth-tier system: worth adding once headcount or volume makes manual tracking unreliable.

**What it does not do:** store files itself or replace a document management platform.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** Where do your documents live now?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - fix naming, ownership and a final-versus-draft rule before adding any new tool. Structure without ownership stays chaotic.
4. **Build only on request** - CSV, SQL DDL, JSON Schema, a Notion mapping or an Excel workbook, data only.

The intended workflow is: Document captured → Named and tagged → Owner assigned → Approved version → Archived

## SQL reference

```sql
CREATE TABLE document_management_system (
  document_title VARCHAR(255),
  document_type VARCHAR(100) NOT NULL,
  employee_name VARCHAR(255),
  department VARCHAR(255),
  uploaded_by VARCHAR(255),
  upload_date DATE NOT NULL,
  signature_required BOOLEAN NOT NULL,
  signed_date DATE NOT NULL,
  version VARCHAR(255),
  storage_link TEXT,
  confidentiality VARCHAR(100) NOT NULL,
  status VARCHAR(100) NOT NULL,
  document_id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_document_management_system_status ON document_management_system (status);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
