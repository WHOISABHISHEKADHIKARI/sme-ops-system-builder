**Policy Library** - a policy library is the single register of every company policy, its owner, its version and the date it was last reviewed. Instead of a spreadsheet only one person understands, each policy becomes a row with a named owner, a status and a review rhythm. 14 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per policy, 14 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 14 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Policy Name`; `Acknowledgement Required`; `Applies To`; `Approver`.
- `Category`; `Compliance Framework`; `Effective Date`; `Next Review`.
- Plus 6 more: `Policy ID`, `Policy Owner`, `Status`, `Summary`, `Version`, `Acknowledgements`.

Field types break down as 1 auto ID, 6 text, 1 long text, 2 select, 1 checkbox, 1 number and 2 date. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Policies live in folders and inboxes, and two people end up enforcing different versions.

That is the argument for policy library: most SMEs have policies in several places and no owner. A register with an owner and a review date makes the gap visible.

Three things break at once without it. Nobody can answer "show me every policy we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per policy fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is under an hour of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A starter-tier system: most small teams need it from day one.

**What it does not do:** provide legal templates or jurisdiction-specific wording.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** Which policies exist today?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - build a register of policies with owner, version and review date. Write the missing policy drafts only for the ones you name.
4. **Build only on request** - CSV, SQL DDL, JSON Schema, a Notion mapping or an Excel workbook, data only.

The intended workflow is: Policy draft → Approve → Publish version → Assign → Review date

## SQL reference

```sql
CREATE TABLE policy_library (
  policy_name VARCHAR(255),
  acknowledgement_required BOOLEAN NOT NULL,
  applies_to VARCHAR(255),
  approver VARCHAR(255),
  category VARCHAR(100) NOT NULL,
  compliance_framework VARCHAR(255),
  effective_date DATE NOT NULL,
  next_review DATE NOT NULL,
  policy_id SERIAL PRIMARY KEY,
  policy_owner VARCHAR(255),
  status VARCHAR(100) NOT NULL,
  summary TEXT,
  version VARCHAR(255),
  acknowledgements NUMERIC NOT NULL,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_policy_library_status ON policy_library (status);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
