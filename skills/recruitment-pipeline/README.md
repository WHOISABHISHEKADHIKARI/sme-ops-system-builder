**Recruitment Pipeline** - a recruitment pipeline tracks every open role and every candidate through the same stages, with scorecards and decision reasons kept alongside. Instead of a spreadsheet only one person understands, each candidate becomes a row with a named owner, a status and a review rhythm. 21 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per candidate, 21 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 21 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Candidate Name`; `AI Match Score`; `Department`; `Email`.
- `Experience (Years)`; `Hired Employee`; `Interview Date`; `Interview Score`.
- Plus 13 more: `Interviewer`, `Notes`, `Notice Period`, `Offered Salary`, `Currency`, `Phone` and 7 more.

Field types break down as 1 auto ID, 8 text, 1 long text, 1 select, 3 number, 2 currency, 2 date, 1 email, 1 web link and 1 relation. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Hiring decisions live in inboxes and interviewers’ heads, so the same question gets asked twice and the best candidate quietly drops out.

That is the argument for recruitment pipeline: the value of a pipeline is knowing where candidates stall. That needs stage transitions with dates, not a CV folder.

Three things break at once without it. Nobody can answer "show me every candidate we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per candidate fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is a couple of hours of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A growth-tier system: worth adding once headcount or volume makes manual tracking unreliable.

**What it does not do:** send emails, schedule interviews or parse resumes.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** How many roles are open right now?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - a pipeline works as stages with a clear exit criterion. Add scoring only if two interviewers need to compare on the same scale.
4. **Build only on request** - CSV, SQL DDL, JSON Schema and a Notion mapping, data only.

The intended workflow is: Apply → Screening → Interview → Offer → Hired

## Frequently asked questions

### What is the difference between recruitment pipeline and a spreadsheet?

A spreadsheet is a container. Recruitment Pipeline is a defined set of 21 fields, a known owner and a stated review rhythm, which is what makes the data trustworthy. The skill emits the same field list as CSV, SQL and JSON Schema so the structure survives the move out of the sheet.

### What fields does a recruitment pipeline system usually include?

At minimum Candidate Name, AI Match Score, Department, Email. A complete version also covers Experience (Years), Hired Employee, Interview Date, Interview Score. This template ships all 21, with types fixed rather than guessed.

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
