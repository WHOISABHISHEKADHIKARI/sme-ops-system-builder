**Mentorship Program** - a mentoring programme matches a mentor and a mentee, sets the goals, and records the sessions so the pairing can be reviewed. Instead of a spreadsheet only one person understands, each mentoring pair becomes a row with a named owner, a status and a review rhythm. 16 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per mentoring pair, 16 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 16 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Mentorship Pair`; `Department`; `End Date`; `Focus Area`.
- `Last Session`; `Mentee Goal`; `Mentee Name`; `Mentor Name`.
- Plus 8 more: `Mentorship ID`, `Next Session`, `Overall Rating`, `Progress Notes`, `Sessions Completed`, `Sessions Planned` and 2 more.

Field types break down as 1 auto ID, 5 text, 1 long text, 1 select, 2 number, 4 date and 2 relation. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Mentoring is announced once and quietly stops after a month.

That is the argument for mentorship program: mentorship fails when pairs are assigned by convenience and never meet. A stated goal for the mentee is what makes a pair worth recording.

Three things break at once without it. Nobody can answer "show me every mentoring pair we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per mentoring pair fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is under an hour of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A scale-tier system: build it when the business already runs on its own data rather than around it.

**What it does not do:** match people automatically or send session reminders.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** How many people want to be mentored?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - match on a stated goal rather than availability, and track only sessions and a closing rating.
4. **Build only on request** - CSV, SQL DDL, JSON Schema, a Notion mapping or an Excel workbook, data only.

The intended workflow is: Mentee goal → Match → Sessions → Mid review → Close with rating

## SQL reference

```sql
CREATE TABLE mentorship_program (
  mentorship_pair VARCHAR(255),
  department VARCHAR(255),
  end_date DATE NOT NULL,
  focus_area VARCHAR(255),
  last_session DATE NOT NULL,
  mentee_goal VARCHAR(255),
  mentee_name VARCHAR(255),  -- relation -> target record
  mentor_name VARCHAR(255),  -- relation -> target record
  mentorship_id SERIAL PRIMARY KEY,
  next_session DATE NOT NULL,
  overall_rating VARCHAR(255),
  progress_notes TEXT,
  sessions_completed NUMERIC NOT NULL,
  sessions_planned NUMERIC NOT NULL,
  start_date DATE NOT NULL,
  status VARCHAR(100) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_mentorship_program_status ON mentorship_program (status);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
