**Audit Log** - an audit log records who changed what and when, as a separate append-only trail that cannot be quietly edited. Instead of a spreadsheet only one person understands, each log entry becomes a row with a named owner, a status and a review rhythm. 11 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per log entry, 11 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 11 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Log Entry`; `Date and Time`; `User`; `Module`.
- `Record`; `Action`; `Field Changed`; `Old Value`.
- Plus 3 more: `New Value`, `Reason`, `Log ID`.

Field types break down as 1 auto ID, 9 text and 1 date and time. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

When something goes wrong, the only evidence is in someone’s sent items.

That is the argument for audit log: audit logs become useless when everything is captured. Start from the question you need to answer, then record only what answers it.

Three things break at once without it. Nobody can answer "show me every log entry we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per log entry fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is under an hour of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A scale-tier system: build it when the business already runs on its own data rather than around it.

**What it does not do:** provide legal assurance of compliance or act as a security control on its own.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** What do you need to be able to prove?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - define the small set of events worth keeping and record who did what and when. Depth follows the question you need to answer.
4. **Build only on request** - CSV, SQL DDL, JSON Schema and a Notion mapping, data only.

The intended workflow is: Event recorded → Actor and time → Stored → Periodically reviewed → Evidence produced

## Frequently asked questions

### What is the difference between audit log and a spreadsheet?

A spreadsheet is a container. Audit Log is a defined set of 11 fields, a known owner and a stated review rhythm, which is what makes the data trustworthy. The skill emits the same field list as CSV, SQL and JSON Schema so the structure survives the move out of the sheet.

### What fields does an audit log system usually include?

At minimum Log Entry, Date and Time, User, Module. A complete version also covers Record, Action, Field Changed, Old Value. This template ships all 11, with types fixed rather than guessed.

### Do I need audit log if my team is small?

Usually yes, and earlier than people expect. Audit Log is a scale-tier system. The deciding question is not headcount, it is whether anyone can answer "show me every log entry we have" without checking with a person first.

### What does this system not do?

- Empty template only. It does not compute payroll, tax, leave balances or KPIs.

## SQL reference

```sql
CREATE TABLE audit_log (
  log_entry VARCHAR(255),
  date_and_time TIMESTAMP NOT NULL,
  user_account VARCHAR(255),
  module VARCHAR(255),
  record VARCHAR(255),
  action VARCHAR(255),
  field_changed VARCHAR(255),
  old_value VARCHAR(255),
  new_value VARCHAR(255),
  reason VARCHAR(255),
  log_id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
