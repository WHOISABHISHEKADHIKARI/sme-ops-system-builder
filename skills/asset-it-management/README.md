**Asset & IT Management** - an asset register records every laptop, phone and device issued to a person, with its serial, warranty and return date. Instead of a spreadsheet only one person understands, each asset becomes a row with a named owner, a status and a review rhythm. 19 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per asset, 19 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 19 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Asset Name`; `Asset ID`; `Asset Type`; `Assigned Date`.
- `Assigned To`; `Linked Accounts`; `Brand/Model`; `Condition`.
- Plus 11 more: `Current Value`, `Department`, `Location`, `Notes`, `Purchase Date`, `Purchase Value` and 5 more.

Field types break down as 1 auto ID, 7 text, 1 long text, 3 select, 2 currency, 4 date and 1 relation. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Equipment leaves with people and nobody notices until the finance year end.

That is the argument for asset and it management: asset registers fail at handover, not at purchase. Tying every asset to a person and a date is what makes it accurate.

Three things break at once without it. Nobody can answer "show me every asset we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per asset fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is a couple of hours of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A growth-tier system: worth adding once headcount or volume makes manual tracking unreliable.

**What it does not do:** image devices, wipe them or enforce MDM policy.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** How many devices does the company own?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - track assets as rows with a serial number and a named holder. Assign on day one, release on exit, and the list stays true.
4. **Build only on request** - CSV, SQL DDL, JSON Schema, a Notion mapping or an Excel workbook, data only.

The intended workflow is: Purchase → Assign to person → Store location → Return on exit → Write-off

  asset_name VARCHAR(255),

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
