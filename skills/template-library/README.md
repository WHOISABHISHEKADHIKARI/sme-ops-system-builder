**Template Library** - a template library stores each recurring document once, with its owner and version, so people stop copying last year’s file. Instead of a spreadsheet only one person understands, each template becomes a row with a named owner, a status and a review rhythm. 9 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per template, 9 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 9 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Template Name`; `Template Type`; `Module`; `Department`.
- `Owner`; `Last Updated`; `Content Link`; `Status`.
- Plus 1 more: `Template ID`.

Field types break down as 1 auto ID, 4 text, 2 select, 1 date and 1 web link. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Documents get recreated from an old attachment, with last year’s figures still in them.

That is the argument for template library: template libraries sprawl when every variant is kept. Keep one current version and an explicit owner, and archive the rest.

Three things break at once without it. Nobody can answer "show me every template we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per template fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is under an hour of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A growth-tier system: worth adding once headcount or volume makes manual tracking unreliable.

**What it does not do:** create or send documents, and does not store files itself.

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - keep one current version per template with a named owner, and start the library with the documents people actually reuse.

## Frequently asked questions

### What is the difference between template library and a spreadsheet?

A spreadsheet is a container. Template Library is a defined set of 9 fields, a known owner and a stated review rhythm, which is what makes the data trustworthy. The skill emits the same field list as CSV, SQL and JSON Schema so the structure survives the move out of the sheet.

### What fields does a template library system usually include?

At minimum Template Name, Template Type, Module, Department. A complete version also covers Owner, Last Updated, Content Link, Status. This template ships all 9, with types fixed rather than guessed.

## SQL reference

```sql
CREATE TABLE template_library (
  template_name VARCHAR(255),
  template_type VARCHAR(100) NOT NULL,
  module VARCHAR(255),
  department VARCHAR(255),
  owner VARCHAR(255),
  last_updated DATE NOT NULL,
  content_link TEXT,
  status VARCHAR(100) NOT NULL,
  template_id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_template_library_status ON template_library (status);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
