**Data Export Engine** - a data export engine records every extract taken from a system, who requested it and what was shared, so data leaving is a controlled act. Instead of a spreadsheet only one person understands, each export becomes a row with a named owner, a status and a review rhythm. 11 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per export, 11 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 11 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Export Name`; `Source Module`; `Requested By`; `Purpose`.
- `Format`; `Date Requested`; `Date Delivered`; `Contains Personal Data`.
- Plus 3 more: `Approved By`, `Status`, `Export ID`.

Field types break down as 1 auto ID, 6 text, 1 select, 1 checkbox and 2 date. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Data leaves through email and never appears on a list.

That is the argument for data export engine: most export requests are one-off. A manual CSV generated from a view solves them; automation is worth it only for a fixed schedule.

Three things break at once without it. Nobody can answer "show me every export we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per export fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is under an hour of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A scale-tier system: build it when the business already runs on its own data rather than around it.

**What it does not do:** connect to any system or run on a schedule without a tool.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** Where does the data need to go?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - for a one-off export, use a generated CSV. Only build a repeating feed when the consumer needs it on a schedule.
4. **Build only on request** - CSV, SQL DDL, JSON Schema, a Notion mapping or an Excel workbook, data only.

The intended workflow is: Scope defined → Exported → Delivered → Consumed or archived

## Frequently asked questions

### What is the difference between data export engine and a spreadsheet?

A spreadsheet is a container. Data Export Engine is a defined set of 11 fields, a known owner and a stated review rhythm, which is what makes the data trustworthy. The skill emits the same field list as CSV, SQL and JSON Schema so the structure survives the move out of the sheet.

### What fields does a data export engine system usually include?

At minimum Export Name, Source Module, Requested By, Purpose. A complete version also covers Format, Date Requested, Date Delivered, Contains Personal Data. This template ships all 11, with types fixed rather than guessed.

## SQL reference

```sql
CREATE TABLE data_export_engine (
  export_name VARCHAR(255),
  source_module VARCHAR(255),
  requested_by VARCHAR(255),
  purpose VARCHAR(255),
  format VARCHAR(255),
  date_requested DATE NOT NULL,
  date_delivered DATE NOT NULL,
  contains_personal_data BOOLEAN NOT NULL,
  approved_by VARCHAR(255),
  status VARCHAR(100) NOT NULL,
  export_id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_data_export_engine_status ON data_export_engine (status);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
