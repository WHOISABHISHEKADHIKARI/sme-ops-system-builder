## What it is

The mark, its lockups, the image library, and the rights behind every asset

## When to use it

- logo, brand mark, wordmark, monogram, symbol, favicon
- lockups, horizontal and stacked versions, one-colour version
- photography library, product photos, team photos, office shots
- icons, illustrations, graphics, patterns
- "we need brand guidelines"
- "can we use this image we found"
- "is this logo already taken"

## How it starts

Opens with one question, then asks only what is still missing - one per message.

> **Q:** What is the business called, and what does one line of it actually do?

- **Identity** - Exact spelling of the name, and any tagline? / What the business does, in one line? / Any name change coming, or a trading name separate from the registered one?
- **Current state** - Is there a logo today, and who made it? / Where is it used - sign, vehicle, invoices, app, uniform? / Does the file still exist in an editable format?
- **Rights** - Does the business already own any marks or registered names? / Any prior designer whose rights were not transferred in writing? / Who signs off the final mark?
- **Imagery** - Do the products or the premises need photographing? / Who is in the photos? Any consent needed? / Is there a real premises to shoot, or is stock acceptable?
- **Delivery** - Which formats and where are they needed - web, print, embroidery, social? / Does anything need to work at very small size?

**Recommended approach:** A trademark search first, then one primary mark with three required variants - full colour, one colour, and a small-size or favicon version - plus a clear-space rule and a minimum size, recorded once and reused everywhere. Alongside it, a photography rule: real premises and real people, shot on a phone, in a fixed set of framings, with the consent record kept next to the images.

**Workflow:** Name and mark searched → Direction chosen → Master mark drawn → Required variants derived → Clear space and minimum size set → Digital and print masters exported → Imagery shot or licensed → Consent and licence recorded per asset → Register approved and versioned

Artifacts are built only after the user asks for them.

## SQL setup

```sql
-- Engine assumption: PostgreSQL. For another engine use the engine's auto-increment
-- equivalent and keep the rest portable.
CREATE TABLE brand_asset (
  id BIGINT PRIMARY KEY,
  asset_name VARCHAR(255) NOT NULL,
  asset_type VARCHAR(100) NOT NULL,
  format VARCHAR(100) NOT NULL,
  dimensions VARCHAR(100),
  aspect_ratio VARCHAR(50),
  colour_mode VARCHAR(100) NOT NULL,
  background_variant VARCHAR(100) NOT NULL,
  minimum_size VARCHAR(50),
  clear_space VARCHAR(255),
  placement TEXT,
  usage_approved TEXT,
  usage_not_approved TEXT,
  source VARCHAR(255),
  rights_owner VARCHAR(255),
  licence VARCHAR(255),
  trademark_status VARCHAR(100) NOT NULL,
  version VARCHAR(50) NOT NULL,
  status VARCHAR(50) NOT NULL,
  notes TEXT,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW(),
  CONSTRAINT asset_trademark_status CHECK (trademark_status IN ('Not searched','Searched - clear','Application filed','Registered','Conflicting mark found','Unknown')),
  CONSTRAINT asset_status CHECK (status IN ('Draft','In review','Approved','Retired'))
);

CREATE INDEX idx_brand_asset_status ON brand_asset (status);
CREATE INDEX idx_brand_asset_type ON brand_asset (asset_type);
```

## Frequently asked questions

### What is the difference between a logo database and a folder of images?

A folder is a container. This is a defined set of 20 fields with a named owner - whoever owns the brand, plus a named approver for trademark use - and a review trigger: whenever the mark, a lockup or a usage rule changes. The same 20 fields are emitted as CSV, SQL, JSON Schema and a Notion mapping, so the four cannot disagree about which version of the mark is current.

### What fields does a brand asset register usually include?

At minimum Asset ID, Asset Name, Asset Type, Format and Dimensions. A complete version also fixes the Colour Mode, Background Variant, Minimum Size and Clear Space rules that decide whether the mark is used correctly, and records Source, Rights Owner, Licence and Trademark Status so a licence question has an answer. This template ships all 20, including Usage Approved and Usage Not Approved so the refusals are written down as well as the permissions.

### Do I need a brand asset register if we are only a two-person business?

Yes - and this is one of the earliest things worth writing down, because the expensive mistakes are made once and then repeated. The deciding question is not headcount, it is whether anyone can answer "which file is the current logo, and are we allowed to print it on a van" without checking with a person first.

### What does this system not do?

It ships an empty template, and it does not:
- search the trademark register or clear a name. `Trademark Status` records the answer once someone has run the search.
- draw, edit or export artwork. It tracks assets that already exist.
- license stock photography. `Licence` records what was bought and whether it was commercial.
- hold photo consent as a first-class record. It notes consent in `Notes` by document number, pending confirmation of how the business keeps those.

### How does it fit with other systems?

It is the asset side of the brand set. `design-theme-guide` holds the colour and type tokens the assets are built from, `brand-kit-print-collateral` the printed items derived from them, and `free-design-resources` the licensed stock and tools available to fill gaps. Each keeps its own table, so a print run can be replaced without touching the asset register.

## Troubleshooting

- Columns show as Text after import - expected, apply the mapping table.
- Dates sort as text - convert the column to Date after import.
- A relation column stays empty - the target has to exist first.
