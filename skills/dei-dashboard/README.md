**DEI Dashboard** - a DEI dashboard records representation and progression by level, so inclusion is tracked as a number rather than asserted. Instead of a spreadsheet only one person understands, each metric becomes a row with a named owner, a status and a review rhythm. 11 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per metric, 11 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 11 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Metric`; `Department`; `Period`; `Measure Type`.
- `Value`; `Target`; `Group Size`; `Minimum Group Size Met`.
- Plus 3 more: `Data Source`, `Notes`, `Metric ID`.

Field types break down as 1 auto ID, 4 text, 1 long text, 1 select, 1 checkbox and 3 number. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Hiring and progression are decided case by case, with no view of the pattern across them.

That is the argument for DEI dashboard: diversity data is easy to collect and easy to misuse. Anonymity and minimum group size are conditions of doing it at all, not nice-to-haves.

Three things break at once without it. Nobody can answer "show me every metric we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per metric fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is under an hour of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A scale-tier system: build it when the business already runs on its own data rather than around it.

**What it does not do:** collect personal data, make hiring decisions or set targets on your behalf.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** Which stages of hiring do you want to look at?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - use voluntary, anonymised data and aggregate to groups large enough to protect people. Skip any breakdown that would identify someone.
4. **Build only on request** - CSV, SQL DDL, JSON Schema and a Notion mapping, data only.

The intended workflow is: Voluntary data → Anonymised aggregation → Stage metrics → Review → Action

## Frequently asked questions

### What is the difference between DEI dashboard and a spreadsheet?

A spreadsheet is a container. DEI Dashboard is a defined set of 11 fields, a known owner and a stated review rhythm, which is what makes the data trustworthy. The skill emits the same field list as CSV, SQL and JSON Schema so the structure survives the move out of the sheet.

### What fields does a DEI dashboard system usually include?

At minimum Metric, Department, Period, Measure Type. A complete version also covers Value, Target, Group Size, Minimum Group Size Met. This template ships all 11, with types fixed rather than guessed.

### Do I need DEI dashboard if my team is small?

Usually yes, and earlier than people expect. DEI Dashboard is a scale-tier system. The deciding question is not headcount, it is whether anyone can answer "show me every metric we have" without checking with a person first.

### What does this system not do?

- Empty template only. It does not compute payroll, tax, leave balances or KPIs.

### How does it fit with other systems?

## When to involve a professional

DEI Dashboard touches decisions with legal, financial or employment consequences. Use the template to organise what you already decided, and confirm the underlying rules with a qualified adviser in your jurisdiction before you rely on them. Local leave, tax, payroll and disciplinary rules differ by country and this page cannot settle them.

## SQL reference

```sql
CREATE TABLE dei_dashboard (
  metric VARCHAR(255),
  department VARCHAR(255),
  period VARCHAR(255),
  measure_type VARCHAR(100) NOT NULL,
  value NUMERIC NOT NULL,
  target NUMERIC NOT NULL,
  group_size NUMERIC NOT NULL,
  minimum_group_size_met BOOLEAN NOT NULL,
  data_source VARCHAR(255),
  notes TEXT,
  metric_id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
