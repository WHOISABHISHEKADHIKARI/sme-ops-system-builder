**Recognition & Rewards** - a recognition record captures who was recognised, for what, by whom and what it cost, so appreciation is consistent rather than ad hoc. Instead of a spreadsheet only one person understands, each recognition becomes a row with a named owner, a status and a review rhythm. 14 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per recognition, 14 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 14 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Recognition Title`; `Category`; `Date`; `Department`.
- `Given By`; `Message`; `Month`; `Notes`.
- Plus 6 more: `Points Awarded`, `Rec-Rwd ID`, `Recognised Employee`, `Reward Type`, `Visibility`, `Year`.

Field types break down as 1 auto ID, 8 text, 1 long text, 2 select, 1 number and 1 date. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Recognition depends on who notices, and the same visible people get noticed repeatedly.

That is the argument for recognition and rewards: recognition programmes fail when entry is effortful. One line at the time of the event is enough; monthly retrospectives are never filled in.

Three things break at once without it. Nobody can answer "show me every recognition we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per recognition fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is under an hour of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A growth-tier system: worth adding once headcount or volume makes manual tracking unreliable.

**What it does not do:** deliver rewards or pay anything.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** How often do you recognise people?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - capture recognition as it happens, with a category so you can see what is being valued over time.
4. **Build only on request** - CSV, SQL DDL, JSON Schema and a Notion mapping, data only.

The intended workflow is: Recognition given → Category → Wall or summary → Monthly review

## SQL reference

```sql
CREATE TABLE recognition_rewards (
  recognition_title VARCHAR(255),
  category VARCHAR(100) NOT NULL,
  date DATE NOT NULL,
  department VARCHAR(255),
  given_by VARCHAR(255),
  message VARCHAR(255),
  month VARCHAR(255),
  notes TEXT,
  points_awarded NUMERIC NOT NULL,
  rec_rwd_id SERIAL PRIMARY KEY,
  recognised_employee VARCHAR(255),
  reward_type VARCHAR(100) NOT NULL,
  visibility VARCHAR(255),
  year VARCHAR(255),
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
