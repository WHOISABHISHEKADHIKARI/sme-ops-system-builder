**Contract & Document Renewal** - a contract register records each agreement, its dates, its renewal notice period and who owns it, so nothing renews by accident. Instead of a spreadsheet only one person understands, each contract becomes a row with a named owner, a status and a review rhythm. 14 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per contract, 14 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 14 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Contract Title`; `Counterparty`; `Contract Type`; `Owner`.
- `Department`; `Start Date`; `End Date`; `Renewal Notice (Days)`.
- Plus 6 more: `Auto-Renew`, `Contract Value`, `Currency`, `Linked Legal Record`, `Status`, `Contract ID`.

Field types break down as 1 auto ID, 5 text, 2 select, 1 checkbox, 1 number, 1 currency, 2 date and 1 relation. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

A contract auto-renews because nobody knew the notice period had to be served in 30 days.

That is the argument for contract and document renewal: renewals are missed because the notice deadline is earlier than the renewal date. Record both and act on the earlier one.

Three things break at once without it. Nobody can answer "show me every contract we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per contract fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is under an hour of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A growth-tier system: worth adding once headcount or volume makes manual tracking unreliable.

**What it does not do:** review contract terms or provide legal advice.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** When is your next renewal?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - track the renewal date, the notice deadline and the owner as one record. Set the notice date as the trigger, not the renewal date.
4. **Build only on request** - CSV, SQL DDL, JSON Schema, a Notion mapping or an Excel workbook, data only.

The intended workflow is: Contract recorded → Notice window → Reminder → Review → Renewed, amended or ended

## SQL reference

```sql
CREATE TABLE contract_document_renewal (
  contract_title VARCHAR(255),
  counterparty VARCHAR(255),
  contract_type VARCHAR(100) NOT NULL,
  owner VARCHAR(255),
  department VARCHAR(255),
  start_date DATE NOT NULL,
  end_date DATE NOT NULL,
  renewal_notice_days NUMERIC NOT NULL,
  auto_renew BOOLEAN NOT NULL,
  contract_value NUMERIC(14,2) NOT NULL,
  currency VARCHAR(255),
  linked_legal_record VARCHAR(255),  -- relation -> target record
  status VARCHAR(100) NOT NULL,
  contract_id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_contract_document_renewal_status ON contract_document_renewal (status);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
