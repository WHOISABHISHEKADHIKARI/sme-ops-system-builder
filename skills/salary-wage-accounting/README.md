## What it is

Payroll booked, paid and reconciled against attendance and statutory liabilities

## When to use it

- payroll register
- salary book
- wage sheet record
- payroll liability tracker

## How it starts

Opens with one question, then asks only what is still missing - one per message.

> **Q:** How many people are on the payroll each month?

- **Workforce** - How many employees? / Salaried or hourly? / Where is attendance recorded?
- **Pay cycle** - When is the run cut? / Who prepares the wage sheet? / Who approves payment?
- **Deductions** - TDS? / SSF/PF or equivalent? / Any advance recovery or other deductions?
- **Statutory** - Who deposits and files? / How often is it reconciled? / Is a liability carried?
- **Outcome** - What do you need? / A payroll record, a liability tracker or both?

**Recommended approach:** One record per employee per pay run holding the period, the days, the gross, the deductions and the net, and let the payroll package do the calculation.

**Workflow:** Attendance recorded → Wage sheet prepared → Approved → Paid → Liability carried → Statutory reconciled

Artifacts are built only after the user asks for them.

## SQL setup

```sql
CREATE TABLE salary_wage_accounting (
  payroll_run VARCHAR(255),
  employee VARCHAR(255),
  employee_id VARCHAR(255),
  department VARCHAR(100) NOT NULL,
  period_start DATE NOT NULL,
  period_end DATE NOT NULL,
  attendance_days NUMERIC,
  paid_days NUMERIC,
  gross_salary_wages NUMERIC(14,2) NOT NULL,
  allowances NUMERIC(14,2) NOT NULL,
  deductions NUMERIC(14,2) NOT NULL,
  tds NUMERIC(14,2) NOT NULL,
  ssf_pf_contribution NUMERIC(14,2) NOT NULL,
  other_deductions NUMERIC(14,2) NOT NULL,
  net_salary_wages NUMERIC(14,2) NOT NULL,
  payment_date DATE,
  payment_mode VARCHAR(100) NOT NULL,
  ledger_account VARCHAR(255),
  approval_reference VARCHAR(255),
  payroll_liability_balance NUMERIC(14,2) NOT NULL,
  statutory_reconciliation_status VARCHAR(100) NOT NULL,
  source_document VARCHAR(255),  -- relation -> target record
  prepared_by VARCHAR(255),
  reviewed_by VARCHAR(255),
  status VARCHAR(100) NOT NULL,
  notes TEXT,
  salary_record_id SERIAL PRIMARY KEY,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_salary_wage_accounting_status ON salary_wage_accounting (status);
```

## Owner and cadence

- Owner: whoever prepares the run, reviewed by a named second person before payment.
- Cadence: one record per employee per pay cycle; statutory reconciliation every month.
- Data: keep the example row until the first real record replaces it. Payroll data stays in
  the payroll system, not in this template.

## Relations

`Source Document` links to the signed wage sheet or the deposit challan.

That target database must exist before the link column resolves in Notion.

- Columns show as Text after import - expected, apply the mapping table.

- Dates sort as text - convert the column to Date after import.
- Net salary does not match the bank file - check the deduction columns before re-typing
  the sheet.

## Frequently asked questions

### What is the difference between salary and wage accounting and a spreadsheet?

A spreadsheet is where the payroll numbers land after somebody else has worked them out. Salary & Wage Accounting is a defined set of 27 fields per employee per pay run that records the decision itself - attendance days against paid days, gross, each deduction, the net, the approval reference - with a named preparer and a second named reviewer before payment. The same fields are emitted as CSV, SQL, JSON Schema and a Notion mapping. The calculation stays in the payroll package; this holds the record of what was decided and what is still owed.

### What fields does a salary and wage accounting system usually include?

At minimum Payroll Run, Employee, Period Start, Period End, Gross Salary/Wages, Deductions, Net Salary/Wages, Payment Date and Status. A complete version splits the deductions into TDS, SSF/PF Contribution and Other Deductions, then adds Attendance Days, Paid Days, Payment Mode, Approval Reference, Payroll Liability Balance and Statutory Reconciliation Status - because the liability that has not been deposited is the figure that quietly grows when nobody tracks it. This template ships all 27, and Source Document is the one relation field, pointing at the signed wage sheet or the deposit challan.

### Do I need salary and wage accounting if my team is small?

Yes - a growth-tier system, and the moment you are running payroll off somebody else's calculations you need a record of the run. The deciding question is whether anyone can answer "what was deducted for TDS this month, and have we deposited it" without checking with a person first. That answer is the difference between a liability reconciled monthly and one that surfaces as a penalty at year end. One record per employee per pay cycle, statutory reconciliation every month.

### What does this system not do?

It ships an empty template and computes or posts nothing. It does not calculate payroll, compute TDS or PF, or pay anyone. It does not file statutory returns or make deposits, and it gives no payroll or tax advice - the calculation and the filing stay with a qualified person, and this only holds the record of what they decided. It never holds real salary or employee data; anyone who needs that works in the payroll system.

### How does it fit with other systems?

It links rather than duplicates. Related modules: `expense-accounting`, `payment-accounting`, `tds-booking-payment` and `source-document-filing`. Each keeps its own table and joins on an ID, so the salary lines land in the expense register as expense rather than payroll, the bank or cash payment that settles the net figure is recorded once, the salary TDS flows into the statutory register and its return, and the signed wage sheet and challan are stored where documents live. Source Document is the one link column, and its target database has to exist before the column resolves.
