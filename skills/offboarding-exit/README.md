**Offboarding & Exit** - an offboarding record turns a departure into a dated checklist covering handover, access, equipment and final pay, so nothing is left open. Instead of a spreadsheet only one person understands, each exit record becomes a row with a named owner, a status and a review rhythm. 18 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per exit record, 18 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 18 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Exit Record`; `Employee Name`; `Department`; `Manager`.
- `Exit Type`; `Notice Date`; `Last Working Day`; `Reason`.
- Plus 10 more: `Handover Owner`, `Knowledge Transfer Done`, `Assets Returned`, `Access Removed`, `Accounts to Close`, `Final Settlement Done` and 4 more.

Field types break down as 1 auto ID, 6 text, 2 select, 6 checkbox, 1 number and 2 date. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Access and equipment belonging to people who left stay open for months.

That is the argument for offboarding and exit: offboarding is the step everyone drops. A dated checklist with a named owner is what stops access, equipment and pay being left open.

Three things break at once without it. Nobody can answer "show me every exit record we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per exit record fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is a couple of hours of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A growth-tier system: worth adding once headcount or volume makes manual tracking unreliable.

**What it does not do:** revoke access itself, terminate employment or provide legal advice on the exit.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** What is the most recent exit?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - run a dated checklist from the agreed last day, and record the exit reason while the person can still be asked for feedback.
4. **Build only on request** - CSV, SQL DDL, JSON Schema, a Notion mapping or an Excel workbook, data only.

The intended workflow is: Exit agreed → Checklist started → Access and equipment closed → Final pay confirmed → Exit recorded and reviewed

## Frequently asked questions

### What is the difference between offboarding and exit and a spreadsheet?

A spreadsheet is a container. Offboarding & Exit is a defined set of 18 fields, a known owner and a stated review rhythm, which is what makes the data trustworthy. The skill emits the same field list as CSV, SQL and JSON Schema so the structure survives the move out of the sheet.

### What fields does an offboarding and exit system usually include?

At minimum Exit Record, Employee Name, Department, Manager. A complete version also covers Exit Type, Notice Date, Last Working Day, Reason. This template ships all 18, with types fixed rather than guessed.

### Do I need offboarding and exit if my team is small?

Usually yes, and earlier than people expect. Offboarding & Exit is a growth-tier system. The deciding question is not headcount, it is whether anyone can answer "show me every exit record we have" without checking with a person first.

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
