**Payroll & Finance** - a payroll register records each pay run by person and period, with the components, the deductions and the net paid, ready for the accountant. Instead of a spreadsheet only one person understands, each payroll record becomes a row with a named owner, a status and a review rhythm. 19 fields, emitted as CSV, SQL, JSON Schema and a Notion mapping from one source, so the four never disagree. This page covers what to track, why teams adopt it, what it costs, and a prompt you can paste straight in.

## What is this

Concretely it is a table, not a document: one row per payroll record, 19 named columns, and the same field list emitted as four artifacts that cannot drift apart.

The 19 fields you would otherwise scatter across a sheet, a chat thread and someone’s memory:

- `Payroll Record`; `Basic Salary`; `Bonus`; `Currency`.
- `DA (Dearness Allowance)`; `Deductions`; `Department`; `Employee Name`.
- Plus 11 more: `HRA`, `Month`, `Net Pay`, `Notes`, `Pay Period`, `Payment Date` and 5 more.

Field types break down as 1 auto ID, 8 text, 1 long text, 2 select, 6 currency and 1 date. Money stays numeric, dates stay dates, and anything that points at another table stays a relation, so the same field list can be emitted as CSV, SQL, JSON Schema or a Notion mapping without the four drifting apart.

## Why we need this

Payroll figures get rebuilt at month end from bank statements and memory.

That is the argument for payroll and finance: payroll is high-risk to compute by hand and cheap to record. Keep this as the register, and let software do the arithmetic.

Three things break at once without it. Nobody can answer "show me every payroll record we have" without checking with a person, the numbers get rebuilt by hand every period, and the person who built the sheet eventually leaves. A named record per payroll record fixes the first, turns the second into a filter, and survives the third.

Adopting it early is cheap. The first version is a couple of hours of work, and no new software is needed, because it starts as a spreadsheet you already own.

## Who this is for

A starter-tier system: most small teams need it from day one.

**What it does not do:** calculate pay, deduct tax or transfer money.

## How it works

The skill runs context first. It identifies the intent, asks **one question per message** for only what is still missing, and stops as soon as the remaining answers would not change the output. Its opening question is:

> **Q:** How many people are on payroll?

Only then does it recommend the smallest workflow, and builds artifacts after you ask:

1. **Identify intent** - is this a new build, a fix, a review or advice?
2. **Ask what is missing** - one question per message, never re-asking anything you already said.
3. **Recommend one approach** - treat payroll as an input record for finance, not a calculator. If you need calculation, use payroll software and record the result.
4. **Build only on request** - CSV, SQL DDL, JSON Schema, a Notion mapping or an Excel workbook, data only.

The intended workflow is: Payroll input → Validation → Payroll run → Register update → Finance and tax

## Frequently asked questions

A spreadsheet is a container. Payroll & Finance is a defined set of 19 fields, a known owner and a stated review rhythm, which is what makes the data trustworthy. The skill emits the same field list as CSV, SQL and JSON Schema so the structure survives the move out of the sheet.

## SQL reference

```sql
CREATE TABLE payroll_finance (
  payroll_record VARCHAR(255),
  basic_salary NUMERIC(14,2) NOT NULL,
  bonus NUMERIC(14,2) NOT NULL,
  currency VARCHAR(255),
  da_dearness_allowance VARCHAR(255),
  deductions NUMERIC(14,2) NOT NULL,
  department VARCHAR(255),
  employee_name VARCHAR(255),
  hra NUMERIC(14,2) NOT NULL,
  month VARCHAR(255),
  net_pay NUMERIC(14,2) NOT NULL,
  notes TEXT,
  pay_period VARCHAR(255),
  payment_date DATE NOT NULL,
  payment_method VARCHAR(100) NOT NULL,
  payroll_id SERIAL PRIMARY KEY,
  status VARCHAR(100) NOT NULL,
  ta_travel_allowance NUMERIC(14,2) NOT NULL,
  year VARCHAR(255),
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_payroll_finance_status ON payroll_finance (status);
```

## Notion setup

1. New page -> Import -> CSV, then pick the exported file.
2. Notion imports every column as Text. That is expected.
3. Apply the property mapping in the skill, one column at a time.
4. Delete the example row once real data is in.

## Troubleshooting

- **Columns show as Text after import** - expected. Apply the mapping table.
- **Relation column stays empty** - the target table has to exist first.
- **Dates sort as text** - convert the column to Date after import.
- **Numbers will not total** - the currency fields are numeric; do not reformat them as text.
